## 轻微问题（MINOR）

### 问题 1：炸弹对炸弹掩码缺失（已在评估前修复）

**发现时间：** 随机 rollout 压测初次运行时
**修复时间：** 评估前（修复后 52 个单元测试全部通过）

**描述：**
`src/engine/action_generator.py` 的 `_check_beats_prev()` 函数，炸弹跟炸弹分支缺少面值比较，导致小炸弹（如 7777）可以跟在大炸弹（如 9999）之后合法出牌。

**修复：**
```python
# 修复前（bug）
if action.formation == FORMATIONS['bomb']:
    return True  # 未区分炸弹跟炸弹

# 修复后
if action.formation == FORMATIONS['bomb']:
    if prev.formation == FORMATIONS['bomb']:
        return action.start_card > prev.start_card  # 面值必须更大
    return True
```

**当前状态：** 已修复，本次 1000 局评估中无此问题出现。

### 问题 2：随机策略下平均 reward 略偏正（4.74）

**出现频率：** 评估期间全程
**严重程度：** 轻微（不影响环境正确性）

**描述：**
在双人对称博弈中，理论上随机策略双方胜率相同，平均 reward 应接近 0。实测环境中 1000 局平均 reward 为 4.74，略偏正值。

**可能原因：**
- 跑得快存在先手轻微优势（发牌后高牌方先出，P0 可能更频繁作为先手）
- rollout 脚本统计视角（从 P0 视角记录 reward）

**影响：** 不影响规则正确性和掩码准确性。AI 训练时双方 reward 符号相反，该轻微偏差将在自我博弈中自然消除。

**建议：** 在基线训练（Stage 6）时，统计先手/后手各自胜率，确认是否存在显著先手优势并相应调整评估设计。

## 改进建议

1. **Stage 6 先手偏差验证**：基线训练后统计 P0/P1 各自胜率，若偏差 > 3%，在评估配置中强制 50/50 先手均等分配（`standard_1k` 评估配置已包含此设计）。

2. **春天率追踪**：在评估脚本中单独统计春天率，作为辅助指标，帮助判断 AI 是否学会了极致压制策略。

3. **obs reward 视角一致性**：训练代码需确保 reward 始终从当前 agent 视角提取（正数=己方赢，负数=己方输），与 `eval_method.md` 第七条「注意事项」对齐。
