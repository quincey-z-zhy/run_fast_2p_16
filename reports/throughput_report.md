# 训练吞吐基准报告

## 测试环境

| 项目 | 配置 |
|------|------|
| GPU | NVIDIA RTX5880-Ada-48Q |
| VRAM | 48 GB |
| CPU | 64 核 |
| PyTorch | 2.11.0+cu128 |
| 测试日期 | 2026-04-16 |

## 测试配置

- n_steps：2048（单次 rollout 的 model 步数）
- batch_size：512
- 网络：ActorCritic MLP（67→256→256→[270, 1]，约 440K 参数）

## 吞吐结果

| 场景 | sps（model 步/秒） | 备注 |
|------|-------------------|------|
| Stage 6 实测（vs random_legal） | 927 | 2M 步 / 2159 秒 |
| 基准测量（vs random_legal） | 877 | 单次 2048 步测量 |
| **Stage 7（vs self-play 对手）** | **614** | 对手模型增加 GPU 推理开销 |

**自博弈额外开销：约 30%**（从 877 降至 614 sps）

## 预估训练时间

| 训练规模 | sps | 预估耗时 |
|----------|-----|---------|
| 2M steps（Stage 6 实测） | 927 | 36 分钟 |
| 5M steps（Stage 7 计划） | 614 | ~136 分钟（≈ 2.3 小时） |

## 吞吐瓶颈分析

Stage 6 吞吐瓶颈在 **CPU 游戏逻辑**（跑得快引擎单线程），而非 GPU。  
Stage 7 引入冻结对手模型后，每步新增一次对手 GPU 前向推理，使吞吐下降约 30%。

具体分析：
- 游戏引擎（CPU）：每步 ~0.9 ms，主要瓶颈
- 学习模型 GPU 推理：每 batch ~0.08 ms
- 对手模型 GPU 推理（Stage 7 新增）：每步 ~0.3 ms 额外开销

## 优化建议

当前吞吐已满足需求（5M steps 约 2.3 小时），无需进一步优化。  
如需加速，可考虑：
1. 多进程并行采样（多个 env 实例同时 rollout）
2. 向量化环境（vectorized env）将 CPU 游戏逻辑并行化
3. 批量对手推理（将多个对手步合并为一次 GPU 批推理）

以上优化均为 Stage 7+ 可选项，不影响当前训练计划。
