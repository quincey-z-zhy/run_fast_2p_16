## 一、游戏特性分析

### 基本特性

| 特性 | 数值 | 影响 |
|------|------|------|
| 玩家数量 | 2 | 适用两人博弈算法框架 |
| 信息结构 | 不完美信息 | 对手手牌私有，own_hand 不可见 |
| obs 维度 | 67 | compact，适合 MLP 神经网络 |
| 动作空间 | 270（固定离散）| action masking 已实现，适合 RL |
| 初始随机性 | 发牌 C(45,15) ≈ 3.4×10⁹ | 需大量对局覆盖状态分布 |
| 回放数据 | 0 局 | 无 SL/Hybrid 前提 |
| 零和性质 | 近似零和（炸弹奖励独立）| 整体接近零和博弈 |

### 信息集规模估算（CFR 可行性）

跑得快的信息集定义为：当前玩家视角下，与其已知信息一致的所有可能完整游戏状态的集合。

- **初始信息集数量（近似）**：player-0 在博弈开始时可能持有的不同手牌计数向量数量，受 DECK_COUNTS 约束下，初始阶段约在 10^5–10^6 量级（注：C(45,15) ≈ 3.4×10^9 是具体发牌局面数，非信息集数量；信息集基于玩家可观测的手牌计数向量，数量更少）
- 随游戏深入，动作序列分支导致信息集数量快速增长，保守估计总信息集数量 ≥ 10^8（超出 tabular CFR 可处理上限）
- 对比：Heads-up Limit Hold'em（已被 tabular CFR 求解）约 10^13 信息集，且使用了大量状态抽象技术

**结论：tabular CFR 不可行；需要深度学习近似（Deep CFR 或 RL）。**

*注：此估算为保守下界。精确信息集计数需要枚举所有合法游戏历史，超出本阶段分析范围，但 tabular CFR 不可行的结论在任何合理估算下均成立。*

### 中文纸牌游戏参考案例

| 游戏 | 算法 | 结果 |
|------|------|------|
| 麻将（Suphx，MSRA 2019）| PPO + 特权信息去除 | 超越大部分顶尖人类玩家 |
| 斗地主（DouZero，IJCAI 2021）| 深度 Monte-Carlo RL + action masking | 超越所有已知程序 |
| 德州扑克（Libratus，2017）| CFR 变体（MCCFR + 蓝图）| 击败顶尖人类 |

跑得快与斗地主/麻将在结构上高度相似（中文纸牌、离散动作、不完美信息），PPO RL 路线已有充分同域验证。

## 二、策略对比

### 候选策略评估总表

| 策略 | GPU 需求 | 前提条件 | 本游戏适用性 | 评分 |
|------|---------|---------|------------|------|
| Heuristic | 无 | 无 | ❌ 策略复杂度过高，无解析最优解 | 1/5 |
| SL | 低 | 大量高质量回放 | ❌ 无回放数据（0 局）| 0/5 |
| CFR（tabular）| 中 | 信息集 ≤ 10^8 | ❌ 信息集 ~3.4×10^9 量级，超出上限 | 1/5 |

### 主路线 vs 备选路线

| | 主路线（PPO 自博弈）| 备选路线（NFSP）|
|---|---|---|
| 算法 | PPO + 自对弈 | Neural FSP（BR + 平均策略）|
| 实现成本 | 低（标准 RL 库）| 中（需双网络）|
| 理论保证 | 经验收敛 | 更强的策略收敛保证 |
| 同域先例 | Suphx、DouZero | 无中文纸牌先例 |
| 触发条件 | 默认主路线 | PPO 1M steps 内无法达到 vs random 40% 胜率 |

## 三、最终决策

### 选定策略：PPO 自我博弈（Deep RL）

**策略标识：** `rl` / `ppo` / `self_play: true`

**决策依据：**

1. **无回放数据约束**：零回放数据排除 SL 和 SL+RL Hybrid 路线
2. **信息集规模约束**：初始局面约 3.4×10^9 种，排除 tabular CFR
3. **实现风险评估**：Deep CFR 无中文纸牌同域先例，信息集抽象设计复杂；PPO 自博弈路线成熟，代码复用性高
4. **实证验证**：Suphx（麻将 PPO）和 DouZero（斗地主 Monte-Carlo RL）在结构相似的游戏中取得超人类水平
5. **基础设施就绪**：Stage 4 已验证 67 维 obs + 270 维 action masking，直接复用
6. **用户偏好对齐**：用户在项目启动时明确选择 PPO 自博弈路线

### 自博弈训练设计摘要

- **对手**：固定的历史检查点池（checkpoint pool）+ 当前策略
- **Reward**：终局得分（稀疏奖励），可选 reward shaping（中间步数奖励）
- **网络结构**：Actor-Critic MLP（共享主干）
- **动作输出**：softmax over 270 维 logits，非法动作 mask 为 -∞
- **训练模式**：两个虚拟玩家同步推进，分别从己方视角累积 trajectory

### PPO 自博弈的理论局限（已知风险，已记录）

PPO 自博弈在理论上不保证收敛到 Nash 均衡——在非传递性博弈图中存在循环风险。这与 CFR/NFSP 的 Nash 收敛保证不同。然而：
- 实证上，Suphx 和 DouZero 在类似中文纸牌游戏中有效收敛
- 评估使用固定检查点池（历史 checkpoints 混合对手）可缓解循环问题
- 若 Stage 6 训练显示胜率停滞或震荡，触发 NFSP 备选路线

此局限已在对抗审查报告（`reports/adversarial_review_stage_5.md`）中记录。

### 备选方案触发条件

若 Stage 6 基线训练中，PPO 在 1M steps 后 vs random_legal 胜率低于 40%（远低于预期 65% 达标线），触发 NFSP 备选路线评估。

## 四、GPU 环境

### GPU 必要性

PPO 自博弈训练的计算需求：
- 自对弈数据吞吐：通常需要 >50,000 steps/sec（CPU 实测 5,252 steps/sec，不足）
- 批量梯度更新：需 GPU 并行加速（否则训练时间过长）
- 典型训练规模：10M-100M steps

**结论：PPO 训练需要 GPU，CPU 训练速度不满足要求。**
