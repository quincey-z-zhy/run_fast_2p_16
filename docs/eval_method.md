# 评估方法文档

版本：v1.0
日期：2026-04-15
状态：待审核

---

## 一、评估目标

评估训练后的 PPO 智能体在两人跑得快中的综合实力，量化其相对基线对手的提升程度，并定义可验收的交付标准。

---

## 二、评估指标

### 主要指标

| 指标 | 计算方式 | 说明 |
|------|----------|------|
| 胜率（Win Rate） | 赢局数 / 总局数 | 核心指标，反映绝对实力 |
| 平均得分（Avg Score） | 所有局总得分 / 总局数 | 反映胜负幅度（春天、炸弹奖励体现） |
| 平均对手剩余牌数 | 赢局中对手剩余手牌均值 | 反映获胜效率 |

### 辅助指标

| 指标 | 计算方式 | 说明 |
|------|----------|------|
| 春天率 | 春天胜局数 / 总局数 | 极端碾压能力 |
| 炸弹使用率 | 炸弹动作数 / 总动作数 | 策略激进程度 |
| Pass 率 | pass 动作数 / 总动作数 | 策略保守程度 |
| 平均局步数 | 总步数 / 总局数 | 间接反映游戏深度 |

---

## 三、基线对手

| 基线名称 | 策略描述 | 用途 |
|---------|---------|------|
| **random_legal** | 从合法动作中均匀随机采样 | 最低基线，训练初期对比 |
| **greedy_low** | 优先出面值最低的合法牌型（尽量不 pass） | 启发式基线，反映朴素策略 |
| **self_v0** | 第一个收敛的 PPO checkpoint | 跨版本自我对弈基线 |

---

## 四、评估配置

| 参数 | 值 | 说明 |
|------|-----|------|
| 对局数/次评估 | 1,000 局 | 统计显著性保证（95% CI 胜率误差 < ±1.5%） |
| 先手分配 | 各 500 局（0 先 / 1 先均等） | 消除先手偏差 |
| 随机种子 | 固定 seed=42 用于可复现评估 | 比较不同 checkpoint 时须用同一 seed |
| 评估频率（训练中） | 每 50k 训练 steps 评估一次 | 记录训练曲线 |

---

## 五、达标标准

| 阶段 | 指标 | 达标线 | 说明 |
|------|------|--------|------|
| 基线训练（Stage 6） | 胜率 vs random_legal | ≥ 65% | 验证训练框架可学习 |
| 正式训练（Stage 7） | 胜率 vs random_legal | ≥ 80% | 正式训练基本质量 |
| 正式训练（Stage 7） | 胜率 vs greedy_low | ≥ 60% | 超越简单启发式策略 |
| 交付标准（Stage 8） | 胜率 vs greedy_low | ≥ 65% | 最终交付要求 |

## 六、评估实现

### 评估脚本位置

`src/eval/evaluate.py`（由 model-training 阶段实现）

### 基线实现位置

`src/eval/baselines.py`

### 报告格式

每次评估产出 JSON：

```json
{
  "checkpoint": "checkpoints/step_100k.pt",
  "eval_seed": 42,
  "num_episodes": 1000,
  "vs_random_legal": {"win_rate": 0.72, "avg_score": 5.3},
  "vs_greedy_low": {"win_rate": 0.61, "avg_score": 4.1},
  "metrics": {"spring_rate": 0.02, "bomb_rate": 0.03, "pass_rate": 0.18}
}
```

---

## 七、注意事项

- 评估时须关闭探索噪声（argmax 而非采样），与训练模式区分
- 若模型与基线双方都允许春天，春天率偏高可能影响胜率方差，增大评估局数至 2000
- 对战双方的 reward 符号相反，注意提取正确的视角得分
